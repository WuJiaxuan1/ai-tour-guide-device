# 小智景点知识库：第一版

## 当前能力

无需重刷 StopWatch。沿用现有小智智能体与 MCP 接入点，新增两个工具：

- `list_qixia_attractions`：列出已收录景点，可按“湖景”“栖霞三宝”等短关键词筛选。
- `get_attraction_guide`：按景点名或别名查询讲解、看点、拍照参考和资料限制。

直接读取 `../ai-tour-guide-device/backend/knowledge/qixia-kb-mvp-v1/`，与网页共用同一份本地知识文件，未复制另一套内容。覆盖明镜湖、钟鼓楼、明征君碑、栖霞寺、舍利塔、千佛岩、乾隆行宫遗址、桃花湖、红叶谷、陆羽茶庄、太虚亭、栖霞老街与古镇。

这是资料查询工具，小智云端模型负责理解问题、决定调用工具、组织回答。不是把资料训练进模型，也不是把整个知识库烧录进手表。来源标签来自现有知识包，本次没有独立复核原始文档。

## 使用时如何工作

游客说“介绍明镜湖” → 手表经 Wi-Fi 上传语音 → 小智云端理解问题并调用 MCP → 本机读取明镜湖资料 → 返回给小智 → 小智组织回答并合成语音 → 手表播放。

电脑和手表不必在同一 Wi-Fi，但都需联网。电脑关机、休眠、停止程序，知识工具就会离线。此版尚未部署 VPS，不会自动与服务器上的知识文件同步。

## 你现在要做的三步

### 1. 启动 MCP

在 VS Code 打开 `D:\Study\yiqifen\mcp-local-demo`。如果旧的 `run_cloud.py` 正在运行，先停止，再重新启动，否则云端仍可能看到旧工具列表。

使用原来的 F5 配置“2. 连接小智 MCP（先填写本机 .env）”。也可以在该目录的 PowerShell 执行：

```powershell
.\.venv\Scripts\python.exe .\run_cloud.py
```

沿用本机 `.env` 中的 MCP 接入点；本次没有更改它，不要把含 token 的地址写入角色提示词或发给别人。若它已失效，从小智控制台更新到本机 `.env` 后再启动。

看到 `Successfully connected` 是连上云端，`ListToolsRequest` 表示云端请求工具目录，提问后出现 `CallToolRequest` 才代表实际调用了工具。连续 `PingRequest` 是正常保活。

### 2. 在手表绑定的小智智能体中补充角色说明

在原角色说明后追加以下内容，保留已有角色和其他功能要求：

```text
你是栖霞山导览助手枫叶精灵。
用户询问栖霞山景点介绍、历史、看点或拍照建议时，优先调用 get_attraction_guide 查阅项目资料，再作答。
不知道有哪些景点时调用 list_qixia_attractions。工具参数使用明确景点名，如明镜湖、栖霞古寺、千佛岩。
用户追问“它”“这里”时，从当前对话确定景点；不能确定就询问，不要猜测用户位置。
首次介绍控制在约20至40秒，口语化讲两三个看点，可问用户是否想听更多。
必须遵守工具返回的 warnings 和 answerRules；资料未提供的年代、数量、传说不要编造。
资料中的拍照建议仅作参考，不当作官方事实。内部字段、来源文件名和核验状态不必逐项朗读。
票价、开放时间、当日枫情、拥挤程度等没有实时数据，明确说明并建议查看景区公告或咨询现场。
工具未连接、查询失败或没有资料时，如实说明，不要声称已经查到。
当前知识工具不提供GPS或路线进度，不要声称知道游客在哪里，也不要自动播报“你已到达”。
```

保存后开始一次新的语音对话。提示词有助于引导工具调用，但实际效果仍需以下云端与真机测试确认。

### 3. 用手表验收

| 你说什么 | 应看到/听到什么 |
| --- | --- |
| 介绍一下明镜湖 | 终端出现工具调用，讲湖面、亭桥与山林倒影 |
| 介绍彩虹明镜 | 能识别为同一个景点 |
| 千佛崖有什么看点 | 能识别千佛岩，介绍石窟与造像 |
| 接着上一问：它适合怎么看 | 根据上一轮景点继续介绍，不乱换地点；资料没有的细节应说明 |
| 红叶谷今天红了吗 | 明确没有当日实况，不保证红叶状态 |
| 栖霞寺具体哪一年建成 | 保留资料存在年份口径差异的限制，不擅自定年份 |
| 介绍一个资料没有的景点 | 说明未查到资料，不编造 |

首次调试可直接说“调用 get_attraction_guide 查询明镜湖”，帮助区分连接问题与模型没有选择工具的问题。正常使用不需要游客说工具名。

## 维护与后续

- `qixia_tools.py`：向小智声明工具；原连接测试工具仍保留。
- `qixia_knowledge.py`：读取资料、匹配名字与别名、返回事实和限制。
- `run_cloud.py` 和官方 `mcp_pipe.py`：保持原云端桥接方式。
- `local_check.py`：真实 stdio MCP 握手与调用测试；不连接云端。
- `test_knowledge.py`：检查别名、缺失资料、资料冲突等边界。
- 后续修改知识包中的资料会在下一次工具查询时读取，无需重新烧录手表。更改工具定义需要重启 MCP。
- 将来部署 VPS：搬迁这个 MCP 服务与知识包，设置 `QIXIA_KB_DIR` 指向服务器知识包目录，并配置常驻服务和接入点。使用同一接入点时先停本机实例。此次未连接或修改服务器。
- 网页当前选中景点、游客 GPS 与自动到点讲解尚未接入；这需要后续设备与游览会话关联，不能仅靠知识库实现。

```powershell
.\.venv\Scripts\python.exe .\local_check.py
```
