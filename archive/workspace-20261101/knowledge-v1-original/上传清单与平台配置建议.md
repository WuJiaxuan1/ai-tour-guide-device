# 上传清单与平台配置建议

## 必须分别创建的知识库

### KB01 景区基础事实库

- 上传：`01_景区基础事实/景区基础事实.md` 或 `01_景区基础事实/knowledge.jsonl`
- 用途：长期稳定的山体、历史、文化、文物与自然科普
- 可以回答：讲解、概况、历史文化、自然科普
- 不可以回答：票价、营业时间、活动、实时枫情、路线耗时

### KB02 景点POI与讲解库

- 上传：`02_景点POI与讲解/景点POI与讲解.md` 或 `02_景点POI与讲解/knowledge.jsonl`
- 用途：每个景点的名称、别名、看点、讲解和坐标
- 可以回答：景点介绍、讲解、别名识别、已知坐标
- 不可以回答：未确认路线连接、动态开放状态

### KB03 服务设施库

- 上传：`03_服务设施/服务设施.md` 或 `03_服务设施/knowledge.jsonl`
- 用途：官方小程序采集的游客中心、卫生间、停车场、餐饮和酒店
- 可以回答：设施名称、位置文字、采集时显示的营业时间
- 不可以回答：实时空位、当前开门状态、未采集的坐标

### KB04 动态运营信息库

- 上传：`04_动态运营/动态运营信息.md` 或 `04_动态运营/knowledge.jsonl`
- 用途：票务、开放、交通、活动、枫情和其他易变信息
- 可以回答：仅在记录仍有效且来源状态满足要求时对客回答
- 不可以回答：将历史快照长期当作当前事实

### KB05 地图核验路段库

- 上传：`05_地图核验路段/地图核验路段.md` 或 `05_地图核验路段/knowledge.jsonl`
- 用途：已有高德步行接口返回的核心路段，不等同于现场实测完整路线
- 可以回答：四个核心POI间的地图步行距离与方向参考
- 不可以回答：扩展成全景区精确导航或无障碍承诺

### KB06 候选路线库

- 上传：`06_候选路线/候选路线.md` 或 `06_候选路线/knowledge.jsonl`
- 用途：AI整理材料和攻略中的路线草案
- 可以回答：行程灵感、路线比较、采风验证对象
- 不可以回答：未经核验的精确导航、固定耗时承诺

### KB07 游客痛点与攻略经验库

- 上传：`07_游客痛点与攻略经验/游客痛点与攻略经验.md` 或 `07_游客痛点与攻略经验/knowledge.jsonl`
- 用途：UGC痛点、用户画像、经验建议、未经核验的美食与活动线索
- 可以回答：风险提醒、追问、个性化建议、调研洞察
- 不可以回答：把主观评价和攻略数字作为官方事实

### KB08 FAQ与决策规则库

- 上传：`08_FAQ与决策规则/FAQ与决策规则.md` 或 `08_FAQ与决策规则/knowledge.jsonl`
- 用途：高频问法、跨库调用规则、兜底话术和安全回答模板
- 可以回答：意图判断、追问、调用顺序、答案组装
- 不可以回答：覆盖事实库中的来源状态和有效期

## 不上传的内容

- `09_待核验与证据/`：后台核验工作台。
- 原始截图、PDF和压缩包：作为证据保存，不直接进入普通RAG。
- 同一个库的Markdown和JSONL通常二选一，避免重复召回。

## 推荐检索优先级

KB04当日官方动态 > KB03官方设施快照 > KB02官方POI > KB01静态事实 > KB05地图路段 > KB06候选路线 > KB07经验建议。KB08负责调度，不与事实来源竞争。
