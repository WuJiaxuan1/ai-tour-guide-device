# P8-avatar-test06：修复摇晃计数被短暂缺读清零

版本：`2.2.6-p8-avatar06`。test05 用户反馈“怎么晃都没有反应”，倾斜和单击/双击正常，但尚未核对实际安装版本。本版修复已复现的缺读容错问题，放宽摇晃阈值，并增加诊断日志。**真机效果待验收**；尚未自动烧录，手机不用更新。

## 问题在哪里

原驱动的“读取失败”也可能只是“这一刻还没有新的加速度数据”。test05 把每一次这样的返回都当作严重中断，清掉累计的摇晃次数。连续倾斜还能正常显示，但需要连续四次反向摆动的眩晕识别可能始终攒不够次数。

此外，test05 要求横向动态加速度至少0.55g、明显大于其他方向，普通手持动作可能达不到。这是代码和模拟测试证明的两个限制；尚无该设备实时日志证明它们就是本次真机现象的唯一原因。

同一段模拟输入的前后对比（2Hz左右往复，2秒）：

| 模拟输入 | test05触发次数 | test06触发次数 |
|---|---:|---:|
| 强摇晃，读数连续 | 1 | 1 |
| 强摇晃，每3次读取缺1次 | 0 | 1 |
| 中等摇晃，读数连续 | 0 | 1 |
| 中等摇晃，每3次读取缺1次 | 0 | 1 |

对应日志为包内 `P8-avatar-test06-before-probe.log` 和 `P8-avatar-test06-after-probe.log`，它们是电脑模拟，不是真机测量。

## 修改

- 短暂没有新数据时保留计数，超过250ms没有有效读数才清掉未完成手势；损坏或明显超量程的数据仍丢弃。
- 力度阈值降至0.32g，横向与其他方向的比例降至1.15，相邻反向摆动允许100～700ms，整组最多2200ms。仍需四次反向摆动，不是晃一下就眩晕。
- 保留3秒冷却和连续650ms拿稳才能重新触发的限制。
- 固定竖直倾斜算法、点按、导航和驱动配置沿用已验收 test04。
- 每2秒输出一条摇晃诊断，包含固件版本和识别过程，不在眼睛界面增加文字。

## 安装与测试

连接设备，关闭占用串口的软件，将 `COM实际端口` 改为当前端口：

```powershell
Set-Location 'D:\Study\yiqifen\stopwatch-nav\releases\P8-avatar-test06'
& 'D:\Study\yiqifen\stopwatch-custom\.tools\espressif\python_env\idf5.5_py3.12_env\Scripts\python.exe' .\flash_p8.py --check-files
& 'D:\Study\yiqifen\stopwatch-custom\.tools\espressif\python_env\idf5.5_py3.12_env\Scripts\python.exe' .\flash_p8.py --flash --port COM实际端口
```

1. 配网后停在语音待机页，不在对话中。竖直拿好，沿屏幕左右方向连续来回摇约1～2秒，停下看是否眩晕并自动恢复。不是只在原地缓慢转动手腕。
2. 拿稳并等3秒，再重复。应能再次触发；持续摇不应一直重播。
3. 普通慢倾斜、拿起放下、走一小段，检查是否误触；阈值放宽后这一项尤其需要真机确认。
4. 眩晕时唤醒或切地图，应立即让位；地图上摇动不触发，切回来不补播。
5. 回归固定竖直倾斜、单击/双击、语音、切页、定位/路线/已走变色。

## 仍无反应时：不用连接手机，采一段日志

设备通过USB接电脑，完成配网停在待机页，执行：

```powershell
& 'D:\Study\yiqifen\stopwatch-custom\.tools\espressif\python_env\idf5.5_py3.12_env\Scripts\python.exe' .\capture_avatar_shake.py --port COM实际端口 --seconds 20
```

20秒内先拿稳约3秒，再左右摇几次，最后拿稳。脚本只保存表情诊断行，不烧录或主动重启；最后显示日志路径。把那份日志交给我即可，不用自己读懂全部字段。

| 字段 | 用来判断什么 |
|---|---|
| `ver=2.2.6-p8-avatar06` | 确认设备实际运行的是这一版 |
| `enabled=1` | 当前允许识别；对话、地图或其他反应期间可能为0 |
| `good/missing/invalid/gap` | 有效读数、缺读、异常读数和最大读数间隔 |
| `peak=x/y/z` | 三个屏幕方向的动态加速度峰值，判断方向和力度 |
| `swings` | 本统计区间识别到的最大摆动计数，目标为4 |
| `event/shown/expired` | 是否识别成功、交给显示线程、因超时被丢弃 |
| `gates/cool` | 是否频繁被状态切换重置，或处于冷却等待 |

各计数/峰值为约2秒的统计区间，不是整次运行累计值。若没有任何诊断行，先核对固件、串口及占用情况，不能直接判定传感器坏了。
