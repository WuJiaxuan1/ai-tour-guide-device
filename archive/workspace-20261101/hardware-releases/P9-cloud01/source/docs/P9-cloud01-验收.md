# P9-cloud01：网页、服务器与手表导航第一版

基线：用户当前的 `2.2.6-p8-overview02`。新固件：`2.2.6-p9-cloud01`。保留开机配网、音量100、小智对话、唤醒词、表情、切页和原局域网地图协议。

## 这一版能做什么

手机浏览器提供 GPS → 项目服务器转换坐标、查询到下一站的高德步行路线并渲染底图 → 手表主动联网同步 → 地图页显示下一段完整路线和定位点。无需运行测试 Android App。

手表约每2.5秒检查一次；实际间隔还包括网络请求耗时。后台生成地图时先返回“准备中”，不会让手表一直等待长请求。第一张图需要高德地图加载时间。

路线和底图分开发送，沿用 QRTE 和 QMAP v4。480像素全览、北朝上、隐藏地图文字、默认14级，路线放不下时缩小；使用 App 默认粉色未走路线、灰色已走路线、蓝色位置点、橙色终点及白色描边。保留地图服务来源标识。此版是“到下一站全览”，不同时显示整条游览行程或巡航窗口。

到达/跳过仍由当前网页行程操作确认；操作后切换下一站。GPS过期、精度不足时隐藏定位点、冻结进度；暂停/结束或失去服务连接时清除活动路线图层。旧底图可能保留作背景。第一版不做自动确认到访、自动重规划或语音主动播报。

## 首次连接本次行程

1. 网页规划路线并开始游览。展开“同步到手表地图”，下载 `stopwatch-navigation.json`。此文件含12小时有效的本次行程凭据，请勿提交到仓库或发到聊天。
2. 手表连上能访问项目服务器的 Wi-Fi，切到地图页。电脑与手表暂时处于同一局域网，找到手表 IP。
3. 电脑执行配置工具，替换下列实际路径和 IP：

```powershell
& 'D:\Study\yiqifen\stopwatch-custom\.tools\espressif\python_env\idf5.5_py3.12_env\Scripts\python.exe' .\configure_cloud.py --config '实际下载目录\stopwatch-navigation.json' --watch-ip '手表IP'
```

如果是本机开发，下载文件中的127.0.0.1对手表无效，需附 `--server-url http://电脑局域网IP:后端端口`，且开发服务须显式监听该局域网。默认本地服务仍仅监听127.0.0.1，不会自动开放防火墙。

正式使用应为有效证书的 HTTPS 域名/地址，固件校验证书，不跳过校验。手机浏览器 GPS 也要求可信 HTTPS；不能把电脑的 localhost 地址直接当作手机可用页面。

4. 手机网页允许定位并保持前台、屏幕开启。配置完成后电脑无需继续参与同步；手表主动连接服务器，可位于另一网络。更换行程或凭据到期后重新下载并配置。
5. 小智语音配对继续使用原来的8位码，与此手表地图配置互不替代。不要同时运行旧 Android App 向同一手表传地图。

## 真机验收（待执行）

1. 配网、音量100、唤醒与对话正常；左右切页和表情保留。
2. 网页开始游览并取得定位后，手表地图页显示到“下一站”的完整路线；网页同步卡显示接收确认。
3. 行走时位置点移动，匹配路线的已走部分变灰；实际GPS偏差需现场检查。
4. 网页确认到达/跳过，下一站变化，手表显示新路线；旧路线不会沿用到新底图。
5. 暂停/结束后活动路线消失；恢复并获取新定位后重建路线。切语音页停止地图传输，切回来能够恢复。
6. 断网、重新联网、重启后可重连（凭据在有效期内）；过期后不再显示活动路线，并可重新配置。

网页的确认表示“地图源已安装、路线数据已接收”，不是物理屏幕截图证明。
