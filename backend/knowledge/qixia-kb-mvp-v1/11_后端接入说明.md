# 后端接入说明

## 结论

知识包不能只上传到RAG；后端需要加载统一ID、景点卡、设施和时间规则。现有高德路线接口继续负责步行折线、距离与时间。

## 必须完成

1. 保留现有景点ID；将 `west-gate` 映射为现有 `gate`。
2. 新增 `bell-drum-tower` 到前端地点目录与 `backend/data/navigation-nodes.json`。导航端点使用钟楼：`[118.957481, 32.151692]`，POI ID `B001912JBJ`；鼓楼是相邻独立POI。
3. 按 `07_id_registry.json` 将知识库设施ID映射为现有 `facility-<高德ID小写>`。
4. 加载 `01_pois_12.jsonl` 提供讲解查询；加载 `03_persona_preferences.json` 和 `04_faq_rules.jsonl` 提供推荐规则。
5. 路线总时长必须使用 `09_time_budget_rules.json`，不能只返回高德步行时间。

## 建议接口

- `POST /api/recommendations`：输入时间、体力、兴趣、用餐需求，返回3-6个点和预计总时长。
- `GET /api/knowledge/pois/:id`：返回30秒讲解、通俗解释和注意事项。
- `GET /api/facilities/nearby`：按当前位置和类型返回设施；只有有坐标记录才能声称“最近”。
- 继续使用现有 `POST /api/navigation/routes`：计算实际步行折线并可优化顺序。

## 总时间计算

`总时间 = 高德步行时间 + 各景点停留 + 用餐 + 计划休息 + 机动时间`。离园前另留15分钟；红叶季周末建议增加15%-20%。

## 当前限制

- 现有路线接口单次支持2至8个不同地点。
- 鼓楼卫生间尚未完成高德实体匹配。
- 高德路线不能替代坡度、台阶、临时封路和实际入口核验。
