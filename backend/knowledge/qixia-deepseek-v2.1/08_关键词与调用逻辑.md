# 问枫枫关键词与调用顺序

先解析对象，再判断意图；先满足当前需求，再补充故事或推荐。触发词只生成候选，不能忽略否定、上下文、时间与实体。

## 统一处理顺序

1. 沿用仍适用的上下文：日期、当前位置、入口、可用时长、离园时间。
2. 找到完整实体：千佛崖卫生间优先于其中的千佛崖；钟楼和鼓楼不能无条件共用坐标。
3. 识别正向需求与否定：不想拍照不激活拍照偏好，不爬山则转低体力约束。
4. 判断多个意图：两小时想拍照以规划为主、摄影为辅；问厕所时先解决厕所。
5. 补问缺失的必要信息：讲故事直接回答；找最近设施才需要当前位置。
6. 检查可用性：动态信息需核验有效期，经验不能升级成官方事实，无坐标不能编距离。
7. 查知识或调工具，按主问题先给结论，再提供相关说明和下一步。

## 容易混淆的说法

| 用户说法 | 正确处理 |
|---|---|
| 红叶为什么会红 | 科普；资料缺少机制细节时只讲已有树种与观察知识，不编造补齐。 |
| 今天红叶红了吗 | 枫情动态，检查日期与当前来源；没有数据就说明未确认。 |
| 现在给我讲讲红叶为什么红 | “现在”可能只修饰对话动作；语义复核后以科普为主，不因关键词产生的动态候选而强制查枫情。 |
| 千佛崖卫生间在哪里 | 设施实体，不能返回千佛岩景点简介。 |
| 千佛斋和一碗素面 | 两个餐饮实体，不因素面描述合并。 |
| 带老人怎么走 | 规划，补问步行与台阶接受度；不自动保证无障碍。 |
| 从栖霞寺到千佛岩怎么走 | 导航，优先处理起终点与实际步行，不先问全部游览偏好。 |
| 只有2小时，想拍照 | 时间预算＋摄影偏好，计拍照停留、回出口和离园预留。 |
| 人间咖啡多少钱 | 商户消费；门票规则不适用，当前材料无可靠最新菜单价格。 |
| 我已经在南门 | 以实际位置为准，默认西门失效；包内无南门入口坐标时需要补定位或地图解析。 |

## 事实与回答的先后关系

同一对象、同一字段、同一适用日期内，优先检查当前官方或现场来源，再比较官方快照、赛方资料/权威资料、地图匹配与经验。没有可比的同一字段时，不机械使用整条记录的全局排名覆盖其他来源。
例如赛方文化资料支持舍利塔石构，不应继续召回旧卡片的木制结构作为当前讲解；地图坐标可以补位置，不能由此证明营业时间或真实入口。

## 复合问题输出次序

对“我们有两小时、带老人、想拍照，附近有厕所吗”：先给当前位置附近已有厕所线索；再确认台阶接受度和离园时间，选择少走路的候选景点；调用路线服务，计算全部时间；最后给沿途拍摄与休息建议。不预设同行者是情侣。
