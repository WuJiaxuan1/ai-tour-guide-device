# 问枫枫 DeepSeek知识包

这份包把栖霞山全量材料整理成DeepSeek消息接口可接收的文字和JSON，不提供额外查询服务，也不要求模型访问本机文件。

## 最直接的用法

将 `04_可直接发送的请求.json` 作为请求正文，发送到 `https://api.deepseek.com/chat/completions`。在请求头配置自己的DeepSeek API密钥，再把 `messages` 中最后一条用户消息改成实际游客的问题。

该JSON已经内嵌完整的系统规则和知识上下文，里面不是文件路径或“请读取某文件”的占位符。示例模型ID是核对时官方文档列出的 `deepseek-flash`；可替换为账号实际可用、支持相同接口的模型ID。本次没有发送付费模型请求。

## 模型收到的逻辑

先识别具体对象 → 判断主意图、辅助意图和否定偏好 → 补问必要信息 → 根据来源与核验状态选择知识 → 回答。

例如：红叶为什么会红查科普；今天红叶红了吗属于动态核验。千佛岩的故事查景点，千佛崖卫生间查设施。两小时想拍照以时间规划为主、拍照为偏好。不想拍照不激活拍照需求。南门已有位置覆盖默认西门。

## 全量与动态的含义

本包仍覆盖全部八类知识，含29个景点目录、53条设施、12个文化专题与16个人物引用。213是记录数量，不是独立事实数。服务表拆分为25个点位，再加其他材料4项得到29项；仅12个景点有坐标。

未核验的12条动态记录（10条运营快照及2条经验库动态线索）在模型上下文中只保留问题范围与“未核验”状态，不带原始价格、运营日期等旧断言。原始材料仍在此前v2.0归档中。完整范围不等于把未经核验的旧数字直接喂成当前答案。

快照、经验、路线候选和回答规则仍分层保留。实时枫情、票价、营业、天气、车位或地图服务没有因此接通；模型应明确未确认，不能假装已调用工具。

## 使用注意

DeepSeek不会因为收到本机路径就自动读取文件；这份请求正文实际传入了文字。模型也不会因一次请求而永久记住知识库。后续请求需要继续携带system知识，或由你们现有平台保存并提供相同上下文。多轮时保留用户和assistant消息，复用仍有效的日期和位置。

本包优先提供全量上下文方式，无需先做向量库。如果你们现有平台限制单次输入长度，可用07文件导入其检索功能，并将01作为应用规则；接口允许的输入长度仍应以实际模型或平台为准。字符数不等于模型token数，本次没有伪造精确token统计。

不要同时重复发送03、01和02：03已经包含01与02。更新知识后，应同步重新生成03和04，避免使用旧的内嵌正文。

## 可选本地示例

Python 3标准库即可，不需要安装SDK。解压后进入本目录：

```bash
python3 调用示例.py "介绍一下明征君碑"
```

这只会生成request.json，不发送网络请求。需要实际调用时，先配置环境变量DEEPSEEK_API_KEY，然后：

```bash
python3 调用示例.py "介绍一下明征君碑" --send
```

密钥不放进知识库、不写进JSON文件。无需把密钥发到聊天里。
