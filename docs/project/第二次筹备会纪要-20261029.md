# 三、路线规划方案

## （一）总体策略：预设路线，演示优先

考虑项目演示性质与时间限制，放弃复杂的实时动态规划，采用类似官方小程序的预设路线方案。从现有小程序扒取 2\-3 条路线作为预设，使用 GPT 筛选这些路线中高频包含的景点，确保预设路径覆盖用户常见选点需求；预设路线必须沿途包含厕所、餐饮等基础设施。对外呈现为个性化定制，实际点位与路线均已提前设计。

## （二）算法逻辑

路径规划不做实时联网算路，分两层实现：一是条件路由，根据出发门、游览时长、体力偏好、是否携带老人小孩等条件，从预设路线库整体匹配对应路线，默认直接返回完整预设路线；二是自选串联，用户在封闭景点池内自行添加点位，系统基于提前离线备好的点位距离矩阵（点对间距离与步行耗时），在前端本地做确定性排序串联，相同选点永远得到相同结果，里程耗时查矩阵累加，不依赖网络与实时定位。用户选点无法被单条预设路线完整覆盖时，以匹配度最高的预设路线兜底，并将多出的点位作为顺路推荐呈现；算法工具经 MCP 接口供大模型调用。

## （三）难度评估与用户入口

结合高德数据，以颜色区分路段坡度，计算台阶或坡道占比，超过特定百分比即提示该路段较困难。设置两个入口：一是行前推荐，用户选择省体力、适中、较难登山步道三档难度后一键生成；二是到点自选，用户从所在门出发自行添加想去的点位，系统在预设优化过的点位范围内规划，用户可自行删减或添加，两种方式不割裂。前端页面无需特别强调双人属性。

## （二）硬件与产品形态

小智手表主要负责语音接收、意图识别及语音输出，复杂的语音流式处理由模型或 API 完成，手表仅承担语音交互、表情交互与导航输出。产品为纯网页端，不开发手机 APP，定位通过用户授权手机浏览器 GPS 权限获取；前端规划好路径后调用高德 API，支持将含途经点的路线导入高德进行步行导航，并需实现前端页面与手表的导航信息同步。当前小智交互以语音为主，网页端直接接入小智模型做文字对话存在技术难度，是否需要为网页非语音交互接入独立模型，由杨金萍进一步调研。

# 五、景点讲解、手账贴纸与记忆系统

## （一）景点讲解与沉浸式彩蛋

景点讲解由用户语音触发小智，小智调用知识库返回景点故事或历史背景，讲解内容严格限定在知识库范围内，避免大模型幻觉。另计划在手机端开发一个独立网页，提供类似"人生模拟器"的剧情互动体验，以历史人物视角通过选项了解景点文化，作为讲解补充彩蛋；Demo 仅针对单个景点制作，网页风格与该景点一致即可，不依赖小智交互。

## （二）手账贴纸（独立功能）

手账贴纸与路线规划完全解耦：用户在前端上传照片，后端通过风格化处理将其转为贴纸风贴图，可直接下载保存用于手账。该功能不读取、不输出任何路线、里程、耗时等行程数据，仅需一个独立的照片上传入口。

## （三）游览记忆与报告

系统记录用户的路线、点位与交互过程，基于预设数据生成游览报告与行程总结。因演示数据均为预设，路线公里数、耗时及回忆内容采用预设值，与手账贴纸功能互不影响。
