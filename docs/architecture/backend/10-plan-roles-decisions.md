# 10 开发计划、任务分工与决策记录

## 1. 分工原则

暂定每个功能模块由 1 名负责人负责，另设 1 名前端设计负责人、1 名小智与网页联调负责人。负责人对模块内实现、测试、文档更新和集成问题负责；其他成员可以协助，但接口责任保持唯一。

将姓名留空，团队确认后填写。

## 3. 2–3 天优先级计划

### 第 0 阶段：开工前（约 1–2 小时）
- 确认仓库结构、启动方式和技术栈。
- 将 `api-spec.md`、`data-model.md` 作为共同契约。
- 每个负责人认领模块和验收条件。
- 前端可先用 Mock 数据并行开发。
- 小智联调负责人先确认现有服务端是否支持自定义工具调用。

### 第 1 天：打通基础链路
目标：后端能启动，知识库与路线推荐 API 可用。
- 建立 FastAPI 骨架、健康检查、配置和测试。
- 导入景点与已核验候选路线。
- 完成路线偏好表单和规则推荐 API。
- 完成景点查询与基础讲解 API。
- 前端使用 Mock 或真实 API 展示结果。

### 第 2 天：完成旅行闭环
目标：用户可保存并推进一次旅行。
- 创建旅行、保存所选路线。
- 下一站、确认到访、跳过。
- 语音/文本笔记保存。
- 生成可编辑旅行摘要。
- 完成前后端集成与主流程测试。

### 第 3 天（如有）：联调与演示
目标：尽可能接入小智，稳定演示。
- 接入 `get_next_stop`、`get_attraction_guide`、`save_voice_note`。
- 完成网页沉浸式讲解页面。
- 修复集成问题、补充失败提示和演示数据。
- 检查密钥、知识库排除规则和数据删除路径。
- 录制或准备演示脚本。

若只有两天，优先完成网页端的端到端业务闭环；小智工具接入按实际能力和剩余时间完成，不应阻塞后端基础功能。

## 4. 模块交付模板

每个负责人完成模块时需提交：
1. 代码和必要配置。
2. 公开 API/函数的输入输出说明。
3. 单元测试或 API 测试。
4. 至少一个正常用例和一个失败用例。
5. 文档变更。
6. 已知限制与未完成事项。
7. 本地运行方式。

## 6. 待确认事项

- 当前小智服务端是否支持自定义工具调用，工具注册方式是什么。
- 当前知识库文件的实际格式与最终导入白名单。
- 地图服务使用高德 API、导航跳转还是两者组合。
- 当前是否有登录系统；若没有，采用哪种演示会话方案。
- 候选路线哪些已核验，老人/儿童适配标签依据是什么。
- 是否需要保存精确位置，以及保留期限。
- 摘要使用哪个模型服务；是否允许调用外部云模型。
- 最终部署环境和演示网络条件。

## 7. 会议与变更规则

- 涉及 API、字段、状态枚举或模块职责变化时，先在团队沟通渠道说明，再更新文档。
- `api-spec.md` 与 `data-model.md` 是开发契约；代码若暂时偏离契约，必须记录原因和后续修复任务。
- 每天至少一次短同步：完成项、阻塞项、接口变化、下一步。
- 演示前冻结接口；紧急变更需同时更新前端、后端和测试。
