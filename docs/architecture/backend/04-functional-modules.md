# 04 功能模块设计

## 1. 模块总览

| 模块 | 主要职责 | 输入 | 输出 | 依赖 |
|---|---|---|---|---|
| M1 交互与意图适配 | 统一网页文本与小智工具请求 | 用户文本、工具参数 | 标准化意图/工具结果 | 前端、小智适配、模型 |
| M2 知识库管理与景点讲解 | 导入、检索、讲解、来源追溯 | 景点 ID、关键词、问题 | 讲解、证据来源、核验状态 | 知识库文件、数据库 |
| M3 路线规划 | 按偏好筛选与排序候选路线 | 入口、时长、强度、同行人、必去点 | 0–3 条候选路线 | 已核验路线数据 |
| M4 旅行管理 | 创建旅行、保存所选路线、开始/暂停/结束 | 用户操作 | 旅行状态与当前路线 | 数据库 |
| M5 地图与位置 | 获取位置、地图展示、导航跳转 | 用户授权坐标、目标点 | 位置状态、导航链接/路线信息 | 浏览器定位、地图服务 |
| M6 行程状态与到访 | 确认到访、跳过、下一站 | 旅行 ID、景点 ID、用户确认 | 到访事件、下一站 | M4、M5 |
| M7 语音笔记 | 保存 ASR 文本或网页输入的笔记 | 文本、旅行/景点上下文 | 笔记记录 | M4、数据库 |
| M8 旅行记忆 | 汇总、编辑、确认、导出、删除旅行记忆 | 旅行、到访、笔记 | 摘要草稿/确认版 | M4、M6、M7 |
| M9 小智集成 | 将语音端工具映射到业务 API | 工具调用、会话上下文 | 工具结果/播报文本 | 小智服务、M1–M8 |
| M10 前端体验 | 偏好表单、路线卡片、地图、沉浸式讲解、行程页面 | 用户操作、API 数据 | 可视化交互 | 所有 API |

## 2. M1：交互与意图适配

### 职责
- 统一网页输入和小智工具调用的业务语义。
- 将模型的工具选择映射到固定的后端函数/API。
- 对工具名称、参数、类型和必填项进行校验。
- 对模型未能判断的请求返回澄清提示。

### 首版范围
- 不开发复杂多 Agent。
- 不让模型直接访问数据库。
- 允许的工具先限制为：
  - `get_next_stop`
  - `get_attraction_guide`
  - `save_voice_note`
- 路线规划首版由网页表单直接调用后端规则 API；后续可增加语音规划工具。

### 验收
- 有效工具名与参数可执行。
- 未知工具、非法参数被拒绝。
- 模型提供的用户/旅行标识不能绕过后端授权。

## 3. M2：知识库管理与景点讲解

### 职责
- 导入现有知识库中的已发布资料。
- 支持景点列表、详情、别名/关键词搜索、讲解检索。
- 讲解结果返回来源、核验状态及证据充分性。
- 支持网页图文沉浸式讲解和小智语音讲解。

### 讲解输出结构
```json
{
  "attraction_id": "example-id",
  "title": "景点标题",
  "answer": "基于资料整理的讲解内容",
  "source_refs": ["知识库文件或条目标识"],
  "verification_status": "verified",
  "evidence_sufficient": true,
  "related_attractions": []
}
```

### 前端沉浸式体验
- 景点详情页可展示标题、正文、图片/音频（仅使用有权使用的素材）、游览提示、相关景点和来源。
- 可从景点卡片、地图标记或行程下一站进入。
- 页面讲解与小智讲解调用同一知识来源，避免两套事实不一致。
- 媒体缺失时优雅退化为文字讲解。

### 验收
- 每条事实可追溯来源。
- 无资料时明确返回证据不足。
- `90_原始材料_禁止上传到RAG` 中任何内容不会进入导入或索引。

## 4. M3：路线规划

### 用户输入
- 入口：西门/南门（枚举值需与核验数据一致）。
- 时长：半天/全天。
- 体力：轻松/正常/能量无限。
- 是否有老人、儿童同行。
- 必去景点：0–2 个。

### 推荐流程
1. 硬性过滤：入口、时长上限、路线状态/核验状态、必去景点覆盖。
2. 安全/适配过滤：有老人或儿童时，仅按有证据支持的路线适配标签过滤；未知适配状态不应伪装成适合。
3. 软性评分：体力匹配、必去点匹配、时长利用率、路线主题差异。
4. 排序后返回 0–3 条；如果只有 1 条符合条件就只返回 1 条。
5. 用户选择路线后才保存到旅行。
6. 大模型只生成推荐说明，不改变结构化路线。

### 路线必备字段
`route_id`、名称、入口/出口、景点顺序、预计时长、体力等级、路线长度/坡度（若已核验）、适配标签、核验状态、来源、最后核验时间。

### 验收
- 不符合硬性条件的路线不会被推荐。
- 不为凑足 3 条而放宽安全约束。
- 无合适路线时给出可调整的条件建议。
- 路线节点与顺序可追溯。

## 5. M4：旅行管理

### 职责
- 创建旅行、读取当前旅行、开始、暂停、恢复、结束。
- 保存用户选中的路线快照，避免候选路线后续更新导致历史行程被意外修改。
- 维护当前旅行状态与时间戳。

### 建议状态
`draft` → `planned` → `active` ↔ `paused` → `completed`。
取消可另设 `cancelled`，需在实现中保持一致。

### 验收
- 不能对不存在或无权访问的旅行操作。
- 已结束旅行不可被普通行程操作意外改写。
- 关键状态变化有时间戳。

## 6. M5：地图与位置

### 职责
- 在用户明确授权后读取浏览器前台位置。
- 将坐标、精度、采集时间提交后端。
- 展示景点位置、当前定位和路线信息。
- 通过地图服务计算路线或跳转导航。

### 首版限制
- 不保证网页在后台持续定位。
- 不保存高频轨迹，除非后续明确提出并完成隐私评估。
- 地图路线结果与业务路线计划分别保存。
- 定位不可用时允许手动选择景点/确认到访。

### 验收
- 拒绝授权、超时、精度差、服务不可用均有可理解提示。
- 不把坐标误差直接当成已到访事实。

## 7. M6：行程状态与到访

### 职责
- 获取下一站。
- 用户确认到访。
- 跳过站点、查看已到访记录。
- 区分计划站点、到访事件和当前导航目标。

### 规则
- 首版以用户手动确认到访为准。
- 同一请求重试不得重复创建相同到访事件（使用幂等键或唯一约束）。
- 下一站按所选路线顺序与已确认/跳过状态计算。
- 若存在多个未完成站点或状态冲突，返回明确状态，不猜测。

### 验收
- 到访记录可查询、可追溯。
- 未确认站点不会显示为已到访。
- 下一站与数据库状态一致。

## 8. M7：语音笔记

### 职责
- 接收小智 ASR 文本或网页文本输入。
- 关联当前旅行和可选景点。
- 保存原始文本、创建时间、输入来源。
- 支持查看、编辑和删除（按权限）。

### 验收
- 不把 ASR 转写内容伪装成模型核验过的事实。
- 保存失败时提示用户，避免静默丢失。
- 同一请求重试按幂等策略处理。

## 9. M8：旅行记忆

### 职责
- 基于真实数据生成旅行摘要草稿。
- 分开保存计划、到访、原始笔记和 AI 摘要。
- 支持编辑、确认、重新生成、查看、导出和删除。

### 规则
- 摘要必须明确实际到访与未确认站点。
- 模型生成失败不能覆盖已确认摘要。
- 生成内容必须可追溯到输入记录。
- 首版不实现跨旅行偏好推断。

### 验收
- 摘要中的已到访景点来自到访记录。
- 用户原话保持独立保存。
- 用户可以修改和删除摘要。

## 10. M9：小智集成

### 职责
- 验证当前小智服务端的工具扩展能力。
- 将工具调用转换为后端业务 API。
- 将结果整理为适合语音播报的短文本。
- 对超时、工具失败和缺少上下文进行友好反馈。

### 首版工具
`get_next_stop`、`get_attraction_guide`、`save_voice_note`。

### 验收
- 语音端调用结果与网页端同一 API 的结果一致。
- 不能仅信任模型传入的 `trip_id`，应从已验证会话/用户上下文中解析并授权。
- 若工具机制暂不可用，网页端业务仍可独立演示。

## 11. M10：前端体验

### 页面建议
- 首页/当前旅行。
- 路线偏好与推荐结果。
- 行程地图与下一站。
- 景点详情与沉浸式讲解。
- 到访记录与语音笔记。
- 旅行记忆查看与编辑。

### 验收
- 加载、空状态、失败状态和权限拒绝状态都有提示。
- 页面不自行推断业务状态，显示以后端返回为准。
- 小屏设备可用，重要按钮易于操作。
