# 旅行回忆事实、摘要与下载契约

这是原后续计划第4项：核对实际到访、时长、语音感受、网页互动与沉浸式记录，验证文字下载与历史重开。照片生成仍为第5项，实时红叶/活动按用户决定暂缓。

## 事实统计

确认景点依据手动确认到访记录，按景点ID去重，排除设施和出入口。确认停靠次数单独展示；同景点重复停靠不重复增加景点数。景点名称沿用旅行路线快照，例如mirror-lake在当前R02中显示“彩虹明镜”。当前/附近GPS和网页体验都不能增加到访数。

总用时为开始至结束（未结束时至当前）；暂停时间单独汇总并包含仍在暂停的时段。活动用时为总用时减暂停，不是纯步行时间。界面/下载按分钟和秒显示，少于60秒为不足1分钟，不上取整成一次完整的1分钟游览。

facts新增 paused_seconds、started_at、ended_at、skipped_stops、interaction_channels、note_channels、note_count、summary_note_count。问答总次数统计所有渠道的已存记录，包括失败尝试；正文只把成功回答作为生成依据。摘要参考最近200条问答（每段问题/回答各最多500字）和最近100条感受，页面在超出窗口时说明覆盖范围。小智普通闲聊未进入旅行工具的内容无法捕获。

interests将成功问答里的游客原话及明确保存的感受结合，要求第一人称肯定表达，排除疑问/否定/假设等明显不适用文本；这是一条保守识别规则，不是通用情绪识别。不能因问得多就宣称最喜欢，不能把“喜欢”升级为“最喜欢”。不符合规则的感受仍作为原话保留。原话中的矛盾或含混不做自动偏好仲裁。

沉浸式记录包含名称、开始/完成时间、完成状态及选择标签。网页展示可展开的选择列表，生成输入保留体验原始快照，仍与实际到访分开。

## 摘要与更新状态

摘要任务在创建时冻结facts、notes、chats、immersive_records及source_record_ids，计算source_fingerprint。结果持久化摘要、模型、生成时间、事实快照、原话感受和指纹。列表API会将结果指纹与当前记录比较，返回summary_stale：true表示有新记录，false表示一致，null表示没有可核对指纹的旧版摘要。状态只提醒，不自动重写历史摘要或产生新模型费用。

同一行程存在排队/运行中的摘要时，新的点击复用该任务，防止两端并发重复生成；相同client_event_id仍幂等。新记录若在生成期间到来，生成结果会标记待更新。失败任务保留错误，新的请求可重试；失败时不返回假摘要。模型提示词要求总时长/活动时长区分，只有明确喜好才能写偏好，体验不能当成到访。事实面板独立于模型文本，便于人工核对。

## 网页与导出

回忆页新增真实记录面板：景点/停靠次数、总/活动/暂停时长、网页与小智问答数量、原话喜好、尚未确认/跳过停靠、体验选择。保留感受与最近问答查看。

“下载本次真实记录”导出当前事实、感受及体验选择，无需模型成功。“下载回忆文字”导出所选摘要及其生成时的事实/感受，避免把旧摘要和新记录混成一个时点。旧版摘要没有新字段时保持可读，不冒称已核验最新资料。历史行程打开/下载不切换当前路线或实物配对。

部署及用户测试见相应memory-r8发布记录。照片界面和图像服务能力保持原状，本项不宣称照片AI创作已完成。
