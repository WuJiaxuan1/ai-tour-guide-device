# 08 安全、隐私与异常处理

## 1. 安全原则

- 服务端是业务权限与状态变更的唯一执行方。
- 大模型输出视为不可信输入。
- 工具采用白名单注册，参数使用 Pydantic schema 校验。
- 用户/旅行上下文从已验证会话解析，不信任模型自行提供的身份或旅行 ID。
- 所有密钥只存环境变量或受控密钥管理服务，不提交到 Git。

## 2. 身份与授权

MVP 若暂时没有完整账号系统，应明确采用哪种受控会话方案，并在演示环境中限制访问。不得仅凭前端传入任意 `user_id` 即认为有权限。
- 读取、修改、删除旅行、笔记、到访和记忆时校验所有权。
- 小智设备会话与网页会话如何映射到用户/旅行，必须有明确方案。
- 任何工具调用都需要服务端鉴权，不因请求来自模型而跳过。

## 3. 定位隐私

- 只有用户授权后才请求浏览器定位。
- 说明定位用途：显示当前位置、辅助行程提示等。
- 默认只保存当前有效位置或用户明确确认的到访位置，不保存连续高频轨迹。
- 不在普通日志中记录完整坐标；如需排障，采用脱敏和短期保留。
- 定位权限拒绝或不可用时，提供手动确认/选择景点的替代路径。
- 坐标、精度和采集时间需要一起处理；低精度定位不能直接判定到访。

## 4. 语音与笔记隐私

- 语音转写文本按用户笔记处理。
- 不将用户原话自动公开或用于其他用户的记忆。
- 明确记录来源是语音转写还是网页输入。
- 提供查看、编辑、删除能力；删除策略覆盖相关摘要或使摘要失效。
- 不记录不必要的原始音频；如需保存音频必须单独评估用途、授权、存储期限和访问控制。

## 5. 模型与工具安全

- 模型只能选择预定义工具，不允许执行任意 SQL、shell 或任意 URL 请求。
- 工具参数必须校验长度、枚举、ID、数值范围和资源归属。
- 对会修改数据的工具（到访确认、保存笔记、删除记录、结束旅行）执行权限与状态校验。
- 对重复请求使用幂等键或唯一约束。
- 工具返回的错误信息不得泄露堆栈、密钥或内部路径。
- 不将检索到的用户可控内容当作系统指令执行。

## 6. 外部服务异常与降级

| 异常 | 系统行为 |
|---|---|
| 大模型不可用/超时 | 返回简短错误；基础查询和已存数据功能尽可能可用 |
| 小智工具调用不支持 | 网页仍可使用业务 API；语音集成作为后续任务 |
| 地图服务不可用 | 显示景点列表与已保存路线，提供重试/外部导航入口（如可用） |
| 定位权限拒绝 | 允许手动选择景点或确认到访 |
| 知识检索无结果 | 说明当前资料不足，不编造答案 |
| 数据库不可用 | 返回服务暂不可用，不假装保存成功 |
| 摘要生成失败 | 保留原始记录和已确认摘要，不覆盖 |
| 没有合适路线 | 返回 0 条及可调整条件，不推荐不符合约束的路线 |

## 7. 日志与错误处理

- 记录请求 ID、模块名、耗时、错误码和必要的诊断信息。
- 避免记录密钥、完整语音内容、敏感定位信息。
- 对客户端返回统一错误结构；开发环境可记录详细异常，生产环境隐藏堆栈。
- 外部 API 调用设置合理超时；有限次数重试，避免无限重试和重复写入。
- 重要写入操作记录创建时间、来源和状态变化。

## 8. 数据生命周期

团队需在实现前确认旅行、笔记、定位和记忆的保留期限。至少支持用户查看和删除自己的笔记与记忆；删除旅行时明确关联记录的级联删除/匿名化策略，并测试其效果。
