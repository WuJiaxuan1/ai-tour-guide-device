## 原版路线与保留同步的衔接

恢复的编辑器先沿原 `/api/routes/plan` 生成道路预览。点击开始时，新增兼容接口 `POST /api/v1/trips/from-selection` 接收：

```json
{
  "client_event_id": "由网页生成并保存用于重试的标识",
  "selection": {"presetId": "R02"},
  "stay_minutes": {"temple": 30}
}
```

自选路线的 `selection` 使用 `stopIds`、`entryId`、`exitId`。服务端使用同一原有道路规划器重建名字、顺序、几何和路段数据；浏览器不能上传伪造的导航快照。停留时长校验为 0–360 分钟且只能指定路线内地点。

创建后沿用原服务端开始命令、定位和设备配对链路。重复开始请求按事件标识复用行程，读取最新状态；设备不可创建行程，其他会话不可读取。游览中/暂停状态禁止编辑，开始失败可用同一请求重试。已有 planned 行程提供“继续已保存行程”，已运行行程刷新后仍恢复。

因此，**只部署前端不足以开始新的自选行程**：未来上线时应同时部署本次后端兼容接口，保留原 SQLite 和配对数据。
