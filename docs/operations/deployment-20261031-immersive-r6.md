## 接口与联调

新增共享文件 `shared/immersive.mjs`，统一体验 ID `temple-ming-life`、景点 ID `temple`、路线上标签及弹窗条件。推荐接口的 `immersive_experiences` 仅在路线含 temple 时返回。旧快照也按实际 stops 判定标签。

`GET /api/v1/experiences` 只返回启用的栖霞寺内容；停用的行宫详情返回404。`POST /trips/:id/immersive` 保存 `experience_id`、可选 `choice_id` 或 `action:restart`，需网页身份、`client_event_id`、`expected_version`。服务器严格按场景转移校验，不能直接跳至完成。

新增 `POST /api/v1/trips/:id/immersive-reminder`，输入 `client_event_id`、`expected_version`、`reminder_id`，可选 `action:open`；无 action 表示暂不体验。提醒状态分别为 opened_on_web / dismissed_on_web。

iframe 只传场景及选择，不传 token。父页校验 origin、source、每次挂载随机 channel；选择收到服务器成功确认后才前进。切换行程后禁止旧体验写入新行程；保存失败显示错误，可关闭重开恢复已存进度。回忆 facts 增加 immersive_experiences，与 visits 分开计数。

## 用户测试顺序

1. 刷新新链接：栖霞寺有胶囊，其他景点没有；点击能打开团队体验。
2. 推荐/选择含栖霞寺的路线（如R02）：路线胶囊可打开同一体验。
3. 在测试行程中完成三次选择，关闭重开确认恢复；完成长按和结尾滑动，回忆页应显示该体验已完成。选择保存为回忆生成的事实输入，现有回忆页不逐条展示所有选择。仅线上体验不增加实地到访数。检查返回游览后音效停止。
4. 另建未手动体验的新测试行程，保持手机网页前台及定位授权；到栖霞寺点位附近至少10秒，收到有效定位后应弹窗。点暂不体验，不再反复弹；仍可手动点击胶囊进入。远程测试不会因点击“我已到达”模拟GPS触发。
5. 配对的小智可询问“栖霞寺有什么沉浸式体验”；待提醒存在时问“我现在在哪”，应提示查看网页。无问句的主动播报不属于本次通过项。
