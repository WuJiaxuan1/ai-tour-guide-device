## 两种方向

### 01 山野旅行手册（建议作为主界面）

- 背景以白色为主，辅以很浅的暖灰；枫红重点操作、深灰绿文字。
- 使用现有景点实拍作为主要视觉，避免每个区块都加插画或嵌套卡片。
- 照片、标题、简短描述、选择操作形成固定的阅读顺序。
- 控件简洁，排版留白有明确用途；桌面探索与路线采用列表和地图两栏。
- 参考色：背景 `#FFFFFF`、浅底 `#F7F5F0`、强调 `#A83F32`、正文 `#2F322D`。
- 适合景区行走途中使用，也便于后续增加真实导航状态。

### 03 秋日手账

- 浅纸色、枫红、温和棕色；使用现有栖霞插画、吉祥物和固定纪念卡。
- 照片可用相纸边缘、少量胶带和轻微倾斜，输入、路线选择和地图控件保持端正。
- 装饰集中在欢迎页和纪念内容，避免地图、列表、每一个按钮都贴纸化。
- 参考色：背景 `#FFFAF0`、浅黄 `#F5E4BC`、强调 `#A84333`、正文 `#493B31`。
- 纪念感更强；若用于全站，需要控制纸纹和装饰密度，并单独检查室外可读性。

建议选 01 作为全站基础，将 03 的纪念感用在专属手账和报告封面。当前未获用户选择，不能视为已经确定的混合方案。

## 分页面规划

| 页面/状态 | 视觉与布局方案 | 必须保留的行为 |
|---|---|---|
| 全局框架 | 顶部品牌与更多、移动端底部三项导航；统一边距与安全区 | 探索、问枫枫、我的路线；历史、关于、报告入口 |
| 问枫枫初始页 | 主视觉＋短标题＋问题行列表＋明确输入框 | 原问题建议、发送/停止、历史会话 |
| 问答进行中 | 回答正文优先，少用大装饰；推荐地点使用紧凑行或照片卡 | 地点详情、选中状态、来源与未知结果；不把只读 MCP 等同于已接通网页自由问答 |
| 探索 | 搜索和分类紧凑排布；紧凑地图可展开；照片卡与地图高亮一致 | 故事/设施切换、天气、定位、收藏、搜索、选择/取消选择、地图归属信息 |
| 详情 | 一张主照片，分明的标题和正文；主要操作稳定 | 相册、已有音频、路线加入/取消、询问枫枫、地图入口 |
| 官方路线 | 四步问题成为视觉主体，下一步保持明确位置 | 入口→时长→体力→同行；逐步跳过；老人儿童组合；未知组合与无匹配的区别 |
| 专属路线 | 入口/出口、纵向停靠点、停留时长、路线操作形成明确顺序 | 官方路线导入、重复经过、增删、重新请求真实道路、既有能力限制 |
| 正在游览 | 地图和下一站优先，操作位置稳定 | 手动到访标识、路线状态、结束游览；不虚构 GPS、里程或手表 ACK |
| 接驳车 | 方向、票价和展开入口清楚，次要说明折叠 | 默认收起、单项展开、真实来源内容 |
| 游览报告 | 封面照片＋指标区域＋沿途内容，与普通弹窗区分 | 固定指标配置与真实统计的边界、现有保存能力 |
| 专属手账 | 照片与纪念卡上下对照；允许纸张与贴纸元素 | 固定图片、本地照片预览、下载；不声称已接图片生成服务 |

预览包含两个方向各六个主要页面/状态与桌面探索版。它用于选方向，尚未覆盖会话、路线结果、弱网、横屏、键盘展开等全部生产状态。

## 后续实施顺序与验收

1. 用户选择方向，并确认是否采用底部主导航、紧凑地图这两项结构提案。
2. 补齐选定方向的桌面、手机、进行中对话、路线结果、专属路线、导航、设施与失败状态概念；具备 Image Gen 工具后按 Build Web Apps 流程制作完整概念。将用户选定稿记录为设计依据。
3. 提取设计变量和公共组件：导航、按钮、输入框、选项、地点卡、地图工具栏、对话框、提示状态。保留既有 React/Vite 架构和素材来源。
4. 先改全局框架与探索，再改路线/问答，最后统一详情、接驳车、报告与手账。逐页比对，避免一次覆盖全部 CSS 后才检查。
5. 构建与已有适用测试通过后，检查 375/390px 手机、短屏、横屏、平板和桌面；检查键盘展开、滚动/吸顶、对话框焦点、地图归属、图片失败和减少动画设置。
6. 验证功能不回归：路线四步、选择取消的一致性、真实道路请求、未核验点位失败、音频、天气、接驳车、报告和本地手账。真实地图/GPS另行验证。
7. 对照批准概念和最终浏览器截图，检查文案、布局、字号字重、配色、照片裁切、间距、图标、状态和响应式；列出有意偏差。只有后续明确要求时再进入部署或 Git 发布。

本规划不扩展路线优化器、不改变后端合同、不替代团队彩蛋。最终路线资料和完整互动彩蛋仍待团队输入。

## 第二轮：秋日手账的层级与排版规划

用户已选全站方向 03，取代初版“方向 01 为主、03 为辅”的建议。当前只提交设计思路，下一批独立预览随后制作，正式网页保持不动。

### 已确认要求

- 三个主页面重新排版，所有文字明确层级并提高字重。
- 圆角随组件尺寸成比例缩放；不同高度的胶囊不共用固定像素圆角。
- 西门、南门改为紧凑内容宽选项；不保留占半屏的大选项卡。
- 首次进入探索页隐藏搜索栏，用户下拉后才出现；具体下拉手势还在确认。
- 官方推荐四步完成并匹配到路线后才显示地图。用户后续补充也将专属路线的初始稿指定为四步选择状态，因此本轮两个路线初始稿均无地图；这是独立预览的交互提案，不直接修改现有生产业务流程。
- 接驳车不显示地图，包括景区内、景区外两类。
- 我的路线中不出现“先选偏好，再查看适合你的官方路线。”及相似的填充性操作说明。
- 每轮交付包含三主页面总览，以及官方推荐、专属路线、接驳车三个分页各自的设计。

### 拟采用的比例与文字系统（待预览验证）

同类组件共享比例，而不是按单个组件手填数值；胶囊和照片/纸张容器使用明确的两类几何规则。

| 组件 | 初拟尺寸 | 圆角规则 |
|---|---|---|
| 小标签 | 28px 高 | 半径 = 高度 × 0.5，即 14px |
| 分类、入口选项 | 36px 高 | 半径 = 高度 × 0.5，即 18px |
| 次要操作 | 40px 高 | 半径 = 高度 × 0.5，即 20px |
| 主操作 | 44px 高 | 半径 = 高度 × 0.5，即 22px |
| 照片和纸张容器 | 随实际排版缩放 | 外圆角初拟为短边 × 0.06；嵌套内框按外圆角减内边距处理，保持同心 |

西门/南门初拟宽 72–80px、高 36px、间隔 8px；文字增长时按内容扩宽。可见控件紧凑，触摸区域仍至少按 44px 高设计，避免相邻命中区重叠。页内导航采用文字与下划线，不将每层导航都画成胶囊。

| 文字角色 | 初拟字号/行高 | 字重 |
|---|---|---|
| 页面主标题 | 28/38px | 650 |
| 当前问题、主要分区标题 | 22/30px | 600 |
| 景点/路线名称 | 18/26px | 600 |
| 正文 | 15/24px | 500 |
| 标签、按钮、页内导航 | 14/20px | 600 |
| 必要辅助信息 | 13/20px | 450–500 |

使用有真实相应字重的中文无衬线字体，避免 300 字重和透明度削弱正文。纸纹放在背景，文本区域保持安静。颜色延续方向 03，正文使用深棕，枫红突出操作与选中状态。

### 间距与亲密关系

- 全页左右边距 20px；窄屏按 16px 复核。
- 名称与对应说明：4–6px。
- 同组控件、图标与文字：8px。
- 标题到本组内容：12px。
- 图片到说明、卡片内边距：12–16px。
- 选项组到下一步：16px。
- 不同任务区之间：24px；只有主要段落转换使用 32px。
- 每组先靠文字和距离建立归属，再判断是否需要边框；不以不断套卡片分组。
- 初始状态选项不预选，下一步保持禁用；用户选择后单独展示选中态，避免用静态稿暗示自动选择。

### 三主页面布局

- 问枫枫：标题和自我介绍成组；插画适度收小；问题建议用紧凑行；输入框靠近建议区域。手账装饰集中在插画，不侵入阅读和输入区域。
- 探索：标题、景点/设施切换、分类构成紧凑浏览区；首次进入无搜索条；照片、景点名、短说明与选择操作作为一个内容单元。天气与定位弱化为单行服务入口。搜索展开状态另出稿。
- 我的路线：页面标题直接衔接三项分页；取消大段副标题、提示口号和重复说明。报告/手账集中到次要入口，不抢路线筛选主任务。

### 我的路线三个分页

- 官方推荐初始态：紧凑四步进度、当前问题、内容宽选项、下一步/跳过；无地图。结果态：已选条件摘要、真实匹配路线、适配当前选中路线的地图；无匹配时不出现泛用地图。
- 专属路线初始态：按用户最新要求展示四步选择、无地图；与官方推荐沿用同一排版体系。完成后的稿件展示入口/出口、停靠点、停留时长和路线编辑。此流程如何复用现有筛选条件，属于后续预览需明确的状态关系，不改后端规则。
- 接驳车：景区内/外切换后直接显示线路列表；每条线路突出名称/方向、起终点和票价，展开后显示站点和运营信息。没有地图和搜索占位，也不重复写“选择一条线路”等说明。

### 下一批预览清单

1. 三主页面总览：问枫枫、探索首屏、我的路线初始态。
2. 我的路线分页专图：官方推荐初始态、专属路线初始态、接驳车列表。
3. 必要状态补图：路线完成四步并匹配后的地图结果、探索搜索栏展开状态。
4. 圆角/字号/间距标注单独放在设计说明区，不放进游客页面。

首次生成以 390px 手机逻辑宽度为主，并复核 375px；每个状态提供可读单图，总览用于比较整体风格。此轮先讲清规划，再生成独立预览，不以源码实现代替设计讨论。
