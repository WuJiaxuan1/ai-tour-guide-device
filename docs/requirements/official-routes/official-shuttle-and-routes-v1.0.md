## 六、需要清洗和核验的问题

### 6.1 名称与 ID

1. **西门入口广场 / 西门游客中心**：可能是同一入口区域的两个节点，也可能是两个独立 POI；必须通过高德 POI ID 和坐标确认，暂时不要合并。
2. **始皇临江 / 始皇临江处**：接驳车和路线使用了不同名称，建议建立同义词，但是否同点仍需坐标确认。
3. **千佛岩 / 千佛崖卫生间**：景点与设施名用字不同，设施应独立建 ID，并把 `near_spot_id` 指向核验后的千佛岩节点。
4. **彩虹明镜 / 明镜湖卫生间**：名称不一致但资料明确关联，仍应拆成景点和设施两个实体。
5. **南山景区上/下行**：这是接驳线路名，不应当成景点节点。

### 6.2 时间字段

- 官方“约 X 小时”是路线级估算。
- 节点“游玩时长”是单点停留建议。
- 截图未提供各节点间步行时间和距离；部分路线的节点停留总和甚至高于官方总时长。
- 后端应重新计算：`总耗时 = 高德分段步行时间 + 各节点停留时间 + 休息/拥堵缓冲`。
- 官方总时长只保留为 `official_duration_minutes`，不要直接作为实时 ETA。

### 6.3 适用人群

- “西门亲子休闲游”也会推荐给 60 岁以上老人，因此路线名称不等于唯一适用人群。
- 建议把适用条件做成单独的 `recommendation_rules`，不要从路线名称猜测。
- “暂无符合条件”目前只在“西门 + 半日 + 正常游览 + 60 岁以上老人”组合中得到明确验证。

## 七、给后端的落地建议

1. 将 8 条路线注册为 `route_id`，路线序列中的重复节点必须保留，以表达折返和回到出口。
2. 景点、入口、厕所、接驳站分别使用独立 ID；通过 `near_spot_id`、`same_place_aliases` 和坐标关系关联。
3. 接驳车线路单独建表，不要混入步行路线节点；推荐时再判断是否可替代某一段步行。
4. 高德 API 用于补齐每一段的步行距离、预计耗时、海拔/坡度替代指标（如有）和 POI ID。
5. 对老人/儿童路线增加硬约束：最大连续步行时间、卫生间间隔、接驳可用性、闭园前返程余量。
6. 所有未在截图中出现的筛选组合标为 `unverified`，不要自动套用相似路线。
