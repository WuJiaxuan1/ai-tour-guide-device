# P8-test02：独立步行路线与实时已走变色

2026-10-30。基线 P7-test07 已由用户验收。P8-test02 在 P8-test01 上增加真实路线进度和已走变色，用户于2026-10-30确认本轮真机验收全部通过。

## 效果与边界

手机搜索地点或输入 GCJ-02 坐标，通过高德 Search SDK 的 `RouteSearchV2.calculateWalkRoute` 规划真实步行路线。显式请求 POLINE 和 COST 字段，使用返回的步行路段坐标；不调用旧 MotoNav 驾车、骑行、蓝牙或导航语音服务。搜索与算路使用已保存的 Android Key，实际权限、额度和景区步行路网覆盖需要真机确认。

路线保留完整首尾与弯折，经1～8米误差的迭代 RDP 简化到最多2048点，超限报错。不能以截断路线或起终点直线假装规划成功。目的地标记使用用户选中的 POI 坐标，可能与规划路线的道路终点有少许距离，不补画虚构连接线。

手表北朝上显示当前位置附近的路线段，地图之外的路线会被裁剪，并非自动缩放显示全程。换块只重新投影，线路不随底图重新下载。手机下方预览绘制相同路线与颜色，上方 SDK 视图继续仅用于准备底图。

可调整未走路线、位置点、终点、描边、已走路线颜色和线宽（手表2～16像素）；RGB滑条或 #RRGGBB，应用后保存。手机根据有效 GPS 将位置匹配到路线折线，手表收到同一进度游标后把前缀绘为已走颜色；手机和手表使用同一条简化后的路线，因此地图移动和换块不会重置进度。手机显示规划总长及预计总时长。本版仍没有剩余距离、转向、到达或自动重算。路线只保留在当前 Activity 内，退出重开需重新选目的地；配色持久保存。

## 数据与状态

`GET /api/v1/status` 增加 `route_protocol:1`、`route_progress_protocol:1`、`route_max_points:2048`、`route_revision`、`route_session`。新 App 要求路线和进度能力；旧 P7 地图/位置协议保持兼容。

`POST /api/v1/route`，Content-Type `application/octet-stream`，整个 QRTE 包一次完整上传。与地图使用同一32位十六进制 session，但不绑定 frame_id，所以同会话换地图块可继续使用路线。路线和配色修改均增加 revision。色彩修改只重传路线包，不重传460800字节底图。

`POST /api/v1/position` 仍发送手机位置；路线已安装时增加 `route_revision` 和 `route_progress`。`route_progress` 是路线点序号之间的浮点游标：0 表示起点，1.5 表示已经走过第1段并走到第2段一半。手机是进度计算的唯一来源：定位需在15秒内、精度不超过25米；路线匹配距离阈值为精度的1.5倍，限制在12～40米。匹配只在上一进度附近寻找，首次前向最多150米，后续由时间和定位精度限制在30～150米，后向寻找30米；重叠线段距离接近时优先保持进度连续。至少推进2米才确认，重复或乱序定位不重复推进。偏离、过期、倒退或跳变不会抹去已走进度。手表只检查当前路线 revision、游标范围和不回退规则，不独立推算第二份进度。

这是路线前缀进度，不是任意行走轨迹记录。长时间断定位后已经走远、绕行后在远处重新加入、完全重叠的往返线路可能无法自动恢复准确进度；可重新规划。本版不做自动重算或完整导航匹配。

所有多字节数值小端，坐标为 IEEE754 float64；RGB 为0xRRGGBB。

| 偏移 | 内容 |
| --- | --- |
| 0～3 | ASCII `QRTE` |
| 4 | 版本1 |
| 5 | 1=路线，0=清除路线/仅更新配色 |
| 6 | 坐标系1=GCJ-02 |
| 7 | 保留0 |
| 8 | revision uint32，1～2000000000 |
| 12 | 点数 uint32，路线2～2048，清除0 |
| 16 | 包总长 uint32，80＋点数×16 |
| 20 | CRC32 uint32，对完整包计算，计算时20～23置0 |
| 24～39 | 16字节 session |
| 40 / 44 / 48 / 52 / 56 | 路线 / 定位 / 终点 / 描边 / 已走 RGB uint32 |
| 60 | 线宽 uint16，2～16 |
| 62 | 标志 uint16：bit0=本次新路线清除旧已走进度，bit1～15必须为0；普通调色置0，同revision重试保持原包 |
| 64 / 72 | 目的地纬度 / 经度；清除时均0 |
| 80起 | 各点纬度、经度，每点16字节 |

bit0仅在设备声明 `route_progress_protocol:1` 后使用。新规划即使几何坐标相同也清零；同revision重传不能再次清零。配色修改沿用原路线进度，地图换块不触发重置。新会话/新启动时可由手机重新发送保留的进度。

成功返回 `service:qixia-stopwatch, protocol:1, type:route_received, boot_id, session, revision, crc32`。位置成功响应在带进度时同时返回 `route_revision` 和 `route_progress`；手机必须匹配这两个字段。表示接收完整并安装到共享状态；UI通过主任务回调或状态刷新绘制，不宣称屏幕物理刷新确认。手机校验确认内容及启动ID。

固件拒绝无效长度、坐标、颜色、版本、CRC、过期会话与旧revision。相同revision与CRC可重试，不同内容不得复用同一revision。接收失败保留旧图层；完整清除包移除路线与终点，但新配色仍作用于位置点。切到语音页、网络服务停止清除路线共享状态，回地图页由手机重发。不同session的地图不得沿用旧路线。

LVGL 使用独立透明绘制层；路线段先投影并裁剪，支持两个端点均在视窗外但穿过视窗的线段。已走/未走分界在裁剪前按原始路线段切开，避免窗口边缘造成错误变色。地图移动时只改变图层偏移，目的地为方形标记，位置为圆点。绘制对象数不随坐标点增长。位置过期隐藏圆点，但保留静态路线和已经确认的已走前缀。
