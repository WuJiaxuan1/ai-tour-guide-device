# P8-avatar-test12：左右平移触发，转手腕不触发

版本：`2.2.6-p8-avatar12`。在最新test11上修改手势，保留test10唤醒恢复、左键语音及触发眩晕时短震。手机App无需更新。本版待真机验收，未自动烧录。

## 这版应该怎么动

在小智待机表情页，手握设备，**屏幕基本保持朝向自己，用手臂带动手表快速左右来回移动**，连续做两三个来回。可先试左右两端相距约20～30厘米的动作，保持周围有足够空间。

- 正确识别后：出现眩晕表情，同时短震一下。
- 原地快速扭动手腕、转动表盘：不应触发眩晕，也不应震动。
- 动画结束后可以再做，不需要切页或重启。
- 只在待机空闲时识别；对话、地图页或其他互动表情播放中不积累动作。

20～30厘米只是便于测试的动作示例，不是固件测得的距离门槛。设备通过加速度和角速度区分平移与转动，不能可靠测出手移动了几厘米。平移时若同时明显转动手腕，也会被拒绝，以满足“转腕不要触发”的要求。

## 实现变化

1. **陀螺仪排除转动**：任意方向的合成转速超过60°/秒，立即丢弃本轮动作；较慢但累计明显的转动也会取消。转动后保留220ms恢复期，防止手腕换向瞬间被当作平移。
2. **持续运动证据**：每一段有效侧向加速度需持续至少60ms，并达到一定累积强度；单个尖峰、短促抖动不算一次有效运动。
3. **允许大幅移动中间的平稳阶段**：相反方向有效加速度之间允许140～1000ms，整段往返最多3.6秒，仍需四次交替的有效运动。
4. **保留短震及自动恢复**：实际显示眩晕时请求一次45ms短震；马达及180ms余振期间隔离传感器互动，避免自己触发自己。

固定竖直倾斜跟随仍使用原来的重力算法。陀螺仪仅用于此次手势排除，不改变眼睛跟随方式。

## 六项验收

1. **平移10次**：屏幕朝向基本不变，左右快速移动两三个来回；等每次动画结束再试下一次。记录成功次数/10。
2. **转腕10次**：保持手的位置基本不变，像之前容易触发的方式快速转动手腕，正反交替。不应出现眩晕或震动；记录误触次数/10。
3. **转腕后再平移**：先转腕几次，停约半秒，再做左右平移。无需切页，仍能触发；重复5轮。
4. **短震与重触发**：每次眩晕开始短震一下，动画中继续移动不会一直震或无限延长动画；播完后可重新触发，倾斜跟随正常。
5. **日常动作**：慢慢倾斜、拿起放下、正常走动和单次轻碰，不应轻易触发。待机的单击/双击表情和短震正常。
6. **语音导航回归**：左键及唤醒词正常；对话和切地图返回后仍能唤醒；地图/路线/已走变色及按键/滑动切页正常。对话或地图页转腕、平移都不触发此互动。

最重要的反馈：**平移成功几次/10，转腕误触几次/10**。

## 如果平移难触发或转腕仍触发

USB连接后采集30秒，前半段做几次转腕，后半段做几次左右平移：

```powershell
& 'D:\Study\yiqifen\stopwatch-custom\.tools\espressif\python_env\idf5.5_py3.12_env\Scripts\python.exe' .\capture_avatar_shake.py --port COM实际端口 --seconds 30
```

日志位于包内`logs`。`ShakeDiag`新增加：

- `gyro`：这一段采样的最大合成角速度，单位°/秒。
- `turning`：当前是否处于转动排除/恢复期。
- `rotation_rejects`：本段因转动取消动作的采样次数，不是转腕次数。

结合已有的`good/missing/gap/swings/event/shown`，可判断是握持转动过多、运动证据不够，还是采样/显示问题。日志命令不烧录、不主动复位，也不记录问答文字。

## 电脑验证及边界

- 用位移正弦轨迹推导加速度，覆盖15/25/40厘米往返距离、不同速度、采样相位、丢样和间隔抖动：216组平移轨迹通过。
- 用转角推导角速度和重力变化，并加入转腕切向加速度，覆盖三轴：108组转动轨迹全部被拒绝；相同模拟中test11仅拒绝54组。
- 平稳移动间隔、单次冲击、短促抖动、无效陀螺仪数据、慢速累计转动、转后平移恢复及诊断检查通过。
- 实际桌面LVGL验证转腕不显示眩晕且不发震动，以及五轮平移触发短震、马达隔离、恢复和页面/语音优先。

这些是模拟传感器输入及电脑界面测试，不能当作真机成功率。实际传感器角速度、握持方式和机械余振仍由本轮验收确认。
