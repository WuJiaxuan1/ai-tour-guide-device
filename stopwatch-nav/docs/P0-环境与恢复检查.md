## 后续可执行的恢复流程

1. 先确认真实 COM 端口及目标设备，确认现有串口工具没有占用。
2. 在首次写入前读取当前设备分区表、OTA 选择，核对布局；必要时另存当前完整备份，使用新文件名，不覆盖历史备份。读回可能使设备重启或进入下载模式，需要告知用户。
3. 若设备布局与已核对的 v2.2.6 布局一致、OTA 状态符合要求，可使用已审阅的恢复助手恢复原版应用和资源：`stopwatch-custom/grok-v5/flash_grok_v5.py` 的 `--restore` 模式，使用已验证的 `.venv-flash` Python 和真实端口。
4. 该助手先读取并检查分区表哈希与 OTA 记录，再写当前应用槽位和配套资源，最后校验。不写 bootloader、分区表、OTA 选择和 NVS。
5. 如果检查不匹配，停止使用这条恢复路径，重新制定匹配的方案；不执行全片擦除或强制跳过检查。
6. 如需按官方方式恢复，参考 https://docs.m5stack.com/zh_CN/guide/stopwatch/restore_factory 。实际按键操作应届时核对官方步骤；不要猜测下载键。
7. 恢复完成后仍需用户验收联网、绑定、唤醒、录音和播放，字节校验通过不能替代功能测试。

当前阶段没有执行上述设备读写流程；旧助手的默认 COM3 不作为设备端口依据。未来模型或分区布局改变后，需重新核对恢复策略，不能永久复用当前假设。
