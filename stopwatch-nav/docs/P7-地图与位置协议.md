P7-test04 方案一：高德相机缩放级别为 15.5，仍裁切中央 240×240，因此范围扩大而线协议不变。手机在位置像素落到 60～180 中央区域之外时提前取下一张底图；旧图继续显示，确认新图后手表以约 360 毫秒淡入替换。该动画只改善换图观感，不能在两张图之间生成新的道路细节。

## 状态与能力

`GET /api/v1/status` 保留原字段：`image_protocol:1` 表示支持 P6 测试图，新增 `geo_protocol:1` 表示支持本协议的地理图像及位置。不能仅凭 `image_protocol` 判断可以发送真实地图。

显示确认仍联合使用 `boot_id`、`image_session` 和 `image_displayed_id`。HTTP 上传成功仅表示完整接收、校验并排队；显示字段表示 LVGL 源安装完成，不是物理屏幕刷新确认。

## 地理图像

`POST /api/v1/image`，Content-Type `application/octet-stream`。真实地图总长度 115296：96 字节头部＋115200 字节 RGB565LE 像素。

前 48 字节沿用 P6：QMAP、版本/类型、格式、宽高、帧编号、像素长度、像素 CRC32、16 字节 session 和保留字节。区别是字节 4 版本为 2，字节 5 类型为 2。格式仍为 1，固定 240×240，帧编号 1～2,000,000,000。40～47 必须为零。

扩展头：

| 偏移 | 类型/长度 | 含义 |
|---|---|---|
| 48 | float64 LE / 8 | north：上边界纬度 |
| 56 | float64 LE / 8 | west：左边界经度 |
| 64 | float64 LE / 8 | south：下边界纬度 |
| 72 | float64 LE / 8 | east：右边界经度 |
| 80 | uint8 / 1 | 1：GCJ-02、北朝上、Web Mercator |
| 81～95 | 15 字节 | 保留，必须为零 |

使用 IEEE754 双精度数；纬度限制在 (-85,85)，经度 [-180,180]，north>south、east>west，各跨度小于 0.1 度，拒绝 NaN/无穷。当前不支持跨日期变更线。CRC32 仍只覆盖像素，地理范围以字段校验和 HTTP/TCP 传输完整性保障，没有新增应用层头部 CRC。

像素从左上到右下逐行存放。边界对应 SDK 投影的屏幕 (0,0) 与 (240,240)，后者是右下边缘，不是最后一个像素中心。手机验证截图完整状态、240×240 尺寸、北朝上/无倾斜、相机未在截图中途变化。高德标识和比例尺保留在截图中。

旧 P6 v1/type1/48 字节头仍可用，明确显示测试图且没有真实位置点。P6 固件不会接受 v2 地理图像，需同时更新 APK 和固件。

## 位置更新

`POST /api/v1/position`，Content-Type `application/json` 或 `application/json; charset=utf-8`，最多 384 字节的平面 JSON。示例为协议样例，不是真实定位：

```json
{"protocol":1,"session":"0123456789abcdef0123456789abcdef","frame_id":24,"seq":1,"valid":true,"lat":32.005,"lng":118.795,"accuracy":8,"age_ms":1000}
```

- session 和 frame_id 必须匹配最后已显示的地理图像，且当前处于地图页。
- seq 为 1～2,000,000,000 的整数，必须大于同一已显示地图的上一序号，防止旧消息覆盖。
- lat/lng 已为 GCJ-02。手机原始 GPS WGS-84 只转换一次，手表不再次偏移。
- accuracy 为米，0～100000；age_ms 为手机发送时已过去的定位时间，整数 0～3600000。
- valid 为布尔值，false 表示撤销定位点。当前手机在无可用定位时发送 false 和零坐标，而不是伪造位置。

手表用自身单调时钟记录接收时间：当前位置年龄=age_ms＋接收后经过时间。有效性要求 valid=true、年龄≤15000ms、accuracy>0 且≤50m。没有使用手机与手表的绝对时钟同步。位置显示约每秒刷新，因此 UI 过期提示可再滞后一个刷新周期；年龄没有估算请求在网络中传输的微小延迟。

成功返回 `service:qixia-stopwatch`、`protocol:1`、`type:position_received`、`boot_id`、`session`、`frame_id` 和 `seq`。表示位置状态已接收，不是屏幕物理确认。地图/会话/序号/页面不匹配为 409；字段不合法为 400；超时/不完整为 408；长度为 413；类型为 415。

图像一旦换成新地图，位置状态重置，等待对应新图的位置。切页、断网或定位失效会取消旧点；没有位置时保留完整底图。点超出地图时隐藏，不把它夹到边缘假装仍在地图内。

## 投影与更新策略

横坐标 `x=(lng-west)/(east-west)*240`。令 `M(lat)=ln(tan(pi/4+lat*pi/360))`，纵坐标 `y=(M(north)-M(lat))/(M(north)-M(south))*240`。双端使用相同公式，北在上、东在右。

手机约每秒串行检查手表状态并发送位置，实际周期还包括 HTTP 耗时。位置落到地图中央 60% 以外时准备新底图，正常相邻截图启动至少间隔 5 秒；用户可手动刷新。地图 SDK 最多等待 25 秒完整截图后重试。旧底图能覆盖当前位置时继续更新点，新底图经确认后替换。

进入语音页后停止新的取图/上传/位置更新，手机可以继续获得 GPS 以便返回时用新位置。手机 App 进入后台或锁屏则整体停止，回前台要手动开始。图像仍使用 P6 的有界 PSRAM 缓冲、完整提交和页面代次保护。

地图来源接口为 `SurroundingMapSource.capture(PhoneFix, callback)`，返回 `MapPixels(pixels,bounds)`。将来服务器模式可以返回同样的像素与范围，设备图像和位置通道可复用；本版仅有手机高德 SDK 实现。
