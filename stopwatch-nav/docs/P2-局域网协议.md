# P2 手机热点局域网协议 v1

阶段：P2-test01。手机主动请求 StopWatch 的 HTTP 服务，端口 8765。当前是小消息链路验收，地图和定位尚未实现。

## 连接与生命周期

- 设备连上 Wi-Fi 并取得 IP 后启动服务；断网或进入配网时停止，重新连上后重启服务。
- 手机用 `GET /api/v1/status` 确认服务身份。成功一次表示当时可达，不表示有持久在线连接。
- App 前台按每次请求完成后约 3 秒的间隔检查状态；请求失败有超时，连接恢复后可重新变为可用。
- 不将手机进程绑定到特定网络，也不影响设备原有小智云端通信。
- 手机 IP 输入暂只支持 IPv4，端口固定，无自动发现。
- App 离开测试页或进入后台后取消当前连接检测，返回后点击“检查连接”继续；暂不实现后台常驻服务。
- IP 改变时需要手动输入新 IP。

## 查询状态

`GET http://<设备IP>:8765/api/v1/status`

```json
{
  "service": "qixia-stopwatch",
  "protocol": 1,
  "firmware": "2.2.6-p2-test01",
  "boot_id": "0123456789abcdef",
  "ip": "192.168.43.123",
  "received_count": 0,
  "last_seq": 0,
  "uptime_ms": 12345
}
```

boot_id 是每次程序启动的诊断标识，不是鉴权凭据。断网重连保留该标识和计数；设备重启生成新标识并清零计数。status 查询不增加 received_count。

## 发送与确认

`POST /api/v1/echo`，Content-Type 为 `application/json` 或 `application/json; charset=utf-8`。

```json
{
  "protocol": 1,
  "type": "ping",
  "session": "0123456789abcdef0123456789abcdef",
  "seq": 1,
  "message": "手机链路测试"
}
```

- 请求体 1～384 字节，UTF-8；仅允许扁平 JSON 对象。
- session 为 32 位小写十六进制字符串，由 App 每次开始检查连接时生成。
- seq 为 1～2,000,000,000 的整数；同次连接中的消息编号递增。
- message 最多 96 字节 UTF-8。

成功返回 HTTP 200：

```json
{
  "service": "qixia-stopwatch",
  "protocol": 1,
  "type": "ack",
  "boot_id": "0123456789abcdef",
  "session": "0123456789abcdef0123456789abcdef",
  "seq": 1,
  "message": "手机链路测试",
  "received_count": 1,
  "uptime_ms": 12346
}
```

App 必须核对 service、protocol、type、session、seq 和 message，不能只看 HTTP 200。手机耗时使用本机单调时钟计算，无需手机和设备校时。

手表屏幕 RX 表示设备收到并处理的有效消息；App 的“已确认”表示手机收到了匹配回复。回复丢失时，手表可能已经计数而 App 显示失败，这是两个不同事实。当前失败消息不自动重发，避免把重发造成的重复计数隐藏起来；本协议尚无去重语义。

## 边界与错误

- HTTP 400：JSON 或字段不合法。
- HTTP 408：请求体未完整收到或接收超时。
- HTTP 413：请求体长度不符合限制。
- HTTP 415：Content-Type 不支持。
- 错误响应为 JSON，含 error 字段；错误请求关闭连接，不增加接收计数。
- HTTP 服务任务优先级 2，栈 6144 字节，最多 3 个客户端 socket；接收/发送等待各 2 秒，读取请求体有总时长检查。
- App 连接/读取超时各 2.5 秒，限制响应为 4096 字节，拒绝重定向和不匹配的回复。
- 网络线程不直接操作音频或 LVGL；计数显示通过 Application 主任务调度。
