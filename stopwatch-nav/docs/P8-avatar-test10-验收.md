# P8-avatar-test10：对话／切地图后的唤醒恢复

版本：`2.2.6-p8-avatar10`。在test09基础上修复，保留左键主动聆听、短震、全屏表情、倾斜、点按、摇晃及地图路线。手机App无需更新。未自动烧录，实际语音识别待真机验收。

## 本次处理的问题

用户反馈：刚开机喊“枫叶精灵”可以，对话或切地图后会失效。

代码检查及电脑回归发现并处理：

1. **识别到了却没有开始聆听。** 待机时如果上一条语音通道仍然打开，旧代码跳过“连接中”状态，但后续函数又只允许该状态进入。识别器已经停止，后续却直接返回。本版统一进入正确流程，再复用已有通道。
2. **连接失败后不能正常重试。** 唤醒或左键连接失败时，明确回到待机并恢复唤醒检测，不停留在“连接中”。
3. **切回小智页的识别窗口残留。** 原来停止只清掉输入缓存，重新开始没有清理MultiNet内部状态。本版在与音频输入同步的锁内清理识别状态，再开始新窗口。
4. **跨页面的旧请求。** 待处理唤醒附带页面代次，切到地图再回来后，不执行上一页遗留的连接请求。连接期间暂停唤醒检测，避免识别结果落在不接受唤醒的状态里。

电脑测试执行实际生产函数，复现了旧版已有通道唤醒失败等分支，并验证修复后通过。测试使用模拟传输和识别器接口，不能据此确定真机遇到问题的全部原因，也不能测量麦克风识别率。

本次保留“枫叶精灵”的词条、模型和识别阈值0.2；不靠降低阈值来掩盖恢复流程问题。首次聆听的短震沿用。

## 六项验收

1. **刚开机**：配网完成、设备进入待机后，说“枫叶精灵”，确认进入聆听并能正常问答。
2. **对话后再次唤醒**：结束一轮对话，等设备回到待机，再说唤醒词；连续做5轮，不需要切页或重启。
3. **切地图后唤醒**：用按键和左右滑动分别往返地图，再说唤醒词，连续做5轮。地图页本身应暂停语音。
4. **中途切地图**：在聆听、回答时切到地图再返回，待机后说唤醒词，应重新开始；不要自动播放上一轮回答。
5. **左键混用**：先用左键开始对话，再回待机用唤醒词开始；来回交替几轮，确认短震和收音正常。
6. **原功能回归**：单击惊讶、双击开心、短震、倾斜、反复摇晃以及地图路线正常；使用约10分钟没有新增卡顿或重启。

当前使用的是自定义词检测：**待机时才用“枫叶精灵”开启对话**；正在聆听时直接说问题即可。小智正在播放回答时，不把“说唤醒词能打断播放”作为本版验收要求，该模式原先就没有开启。

可选：在小智已就绪后暂时断开热点的上网连接，尝试开始对话；恢复网络并等待回到待机后再喊唤醒词，确认能重试。网络恢复所需时间取决于热点与云端连接。

## 如果仍会失效：记录60秒诊断日志

USB连接电脑、关闭串口占用，运行下面命令。在60秒内依次做“唤醒→对话→切地图→返回→再次唤醒”：

```powershell
& 'D:\Study\yiqifen\stopwatch-custom\.tools\espressif\python_env\idf5.5_py3.12_env\Scripts\python.exe' .\capture_wake_recovery.py --port COM实际端口 --seconds 60
```

日志保存在包目录的`logs`中。仅记录识别器启停、唤醒命中、设备状态、切页和相关初始化错误；不保存问答文字或录音。不烧录，不主动复位设备。

- 有`Custom wake word detected`：本地已识别到，再检查是否进入`listening`。
- 返回后有`detector started with fresh recognition state`：已执行识别器重启；这不等于已经证明声音识别正常。
- 没有命中日志：还需要结合距离、环境和设备采音继续定位，不直接归因为灵敏度。

反馈时说明第几项失败、是完全无反应还是进入聆听后没回答，并提供生成的诊断日志。
