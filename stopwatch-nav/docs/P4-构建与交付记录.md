## 实现

基础提交仍为 `356541a94d6ea73f291388eb028a670e6c75f2f3`，分支 `dev/p4-maple-wakeword`，版本 `2.2.6-p4-test01`。

本阶段复用上游 `CustomWakeWord` 和乐鑫 ESP-SR 中文 MultiNet7，没有重新训练模型或重写音频流程。修改当前 sdkconfig 和可复现配置 sdkconfig.stopwatch：

```text
CONFIG_USE_CUSTOM_WAKE_WORD=y
CONFIG_CUSTOM_WAKE_WORD="feng ye jing ling"
CONFIG_CUSTOM_WAKE_WORD_DISPLAY="枫叶精灵"
CONFIG_CUSTOM_WAKE_WORD_THRESHOLD=20
CONFIG_SR_MN_CN_MULTINET7_QUANT=y
```

原 AFE WakeNet 实现选择关闭，中文 MultiNet 的 NONE 选择关闭；保留 SEND_WAKE_WORD_DATA。阈值 20% 沿用上游默认，不等同识别准确率；根据实测漏唤醒与误唤醒情况再调。

上游资源生成器根据配置打包 `mn7_cn` 和 `fst`，index.json 写入中文命令、3000ms 识别窗口和 0.2 阈值。AudioService 在实际资源含 MultiNet 模型时创建 CustomWakeWord，初始化时读取资源中的命令配置。检测后沿用原唤醒回调、云端会话和录音播放链路。

因此必须成对写入程序和资源，程序版本号本身不能证明新词已生效。包内不再包含旧的 WakeNet 唤醒模型；字体和表情保持原样。手表局域网状态标签改为 P4，通信协议保持不变。

P3 配网组件逐文件哈希与已验收包一致；每次开机清 Wi-Fi、本次运行重连、保存后切手机热点的行为继续使用。自动固件替换仍按前序实现跳过；原有手动资源更新功能不属于本阶段改造，测试期间不要另行替换语音资源。

## 构建与验证

- ESP-IDF 5.5.2 构建成功，程序 2,963,376 字节；应用槽 0x3f0000，约 28% 余量。
- 资源 5,242,378 字节，小于 0x800000 资源分区；分区布局与 P3 相同。
- `test_wake_assets.py` 读取实际生成资源，核对模型目录、文件表、偏移和每个文件字节与依赖中的 mn7_cn/FST 一致；SR 模型包 2,681,351 字节。
- 核对资源实际命令为 `feng ye jing ling` / “枫叶精灵” / wake，语言 cn、时长 3000、阈值 0.2；核对字体、表情、其他 index 配置与 P3 一致。
- 验证旧 P3 资源包不能作为 P4 新词资源通过检查，截断的模型文件被拒绝。
- 七项发布保护测试通过，发布文件及 P3 回退文件大小与 SHA256 校验通过；源码空白检查通过。

以上不能验证 ESP32 模型初始化、声学识别效果或运行内存。现有运行日志会打印命令、识别结果和 SRAM 统计；待真机反馈核对。Flash 容量余量不能用来宣称 PSRAM 或 SRAM 余量充足。
