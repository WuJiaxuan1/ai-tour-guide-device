# P6 单张测试图协议

状态：2026-10-27，P6-test01 已构建并通过离线检查，待真机验收。

手机作为 HTTP 客户端，主动向手表 IP 的 8765 端口上传。手表连接手机热点，小智云端仍通过热点访问互联网。没有自建服务器或 MCP 参与图像传输。

## 请求

`POST /api/v1/image`，Content-Type 为 `application/octet-stream`，Content-Length 必须为 115248。只在地图页接收。

头部 48 字节，整数均为小端：

| 字节偏移 | 长度 | 含义 |
|---|---:|---|
| 0 | 4 | ASCII QMAP |
| 4 | 1 | 协议版本 1 |
| 5 | 1 | 类型 1：合成测试图 |
| 6 | 1 | 格式 1：RGB565LE |
| 7 | 1 | 保留，必须为 0 |
| 8 | 2 | 宽度 240 |
| 10 | 2 | 高度 240 |
| 12 | 4 | frame_id，范围 1～2,000,000,000 |
| 16 | 4 | 像素长度 115200 |
| 20 | 4 | 像素数据 CRC32 IEEE |
| 24 | 16 | session 二进制值，在 JSON 中表示为 32 位小写十六进制 |
| 40 | 8 | 保留，全部为 0 |

头部后紧接 240×240×2 字节像素，从左上角开始逐行排列。每个像素红 5 位、绿 6 位、蓝 5 位，低字节在前；纯红 F800 对应字节 00 F8，纯绿 07E0 对应 E0 07，纯蓝 001F 对应 1F 00。CRC32 只覆盖像素数据，标准校验向量 ASCII `123456789` 为 CBF43926。

P6 不携带经纬度、地理范围、坐标系或位置时间，不能用本协议的测试类型假称真实地图。P7 接入真实地理数据时须扩展协议并联合定义地图范围和位置对应关系。

## 确认和状态

上传成功响应包括 `service: qixia-stopwatch`、`protocol: 1`、`type: image_received`、`state: queued`、`boot_id`、`session`、`frame_id`、`crc32`。这只表示接收完整且校验成功、等待主任务处理。

`GET /api/v1/status` 保留原 P2 字段，新增 `image_protocol: 1`、`map_active`、`image_pending`、`image_received_id`、`image_displayed_id`、`image_session`。其中 image_session 属于最后一张已交给 LVGL 的图。手机使用 boot_id、session 和 frame_id 联合确认，不只比较编号。显示状态表示 LVGL 数据源安装完成，不是屏幕物理刷新回执。

手机收到上传 ACK 后最多查询 12 次显示状态，两次间隔 500ms，另有 HTTP 请求耗时。离开地图页、设备重启或未确认显示时报告失败/未确认，不自动重传。晚到的取消不撤销已经安装的完整图片。

## 错误和缓冲

| HTTP 状态 | 含义 |
|---|---|
| 400 | 头部、字段或 CRC 错误 |
| 408 | 接收超时或不完整 |
| 409 | 非地图页、待显示队列占用或接收期间页面代次改变 |
| 413 | 总长度不符 |
| 415 | Content-Type 不支持 |
| 503 | 图像缓冲分配失败 |

网络任务分块接收，每块最多 4096 字节，总接收期限 8 秒，单次接收超时 2 秒。完整校验后才提交到只有一个槽位的待显示队列。切页或停止网络服务会使旧代次失效，避免过期传输在返回地图后突然显示。

像素显式分配在 PSRAM，以共享所有权保持 LVGL 使用期间的生命周期。最多为已显示、待显示、正在接收各一张，像素数据合计约 345600 字节，另有元数据和系统开销。换图时清理 LVGL 图像缓存；失败保留上一张完整图，重启清空 RAM 缓存。
