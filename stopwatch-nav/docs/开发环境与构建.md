# 开发环境与构建

当前源码对应已验收的 P8-test02（2026-10-30）：Android `8.3.26-p8-test02` / versionCode 142；固件 `2.2.6-p8-test02`。本次入库没有改动已验收的业务代码。

## Android

安装 Android Studio，准备 JDK 21、Android SDK 35 与 Build Tools 35.0.0。项目使用 Gradle Wrapper；首次构建需联网下载依赖。Android Studio 打开 `stopwatch-nav/android/`，按本机 SDK 路径生成 `local.properties`，或配置 `ANDROID_HOME`。

在 `android/` 执行：

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest
```

APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。新电脑会生成自己的 `.local/debug.keystore`，不与已安装版本自动共享签名。要覆盖安装现有演示 App，需由负责人单独提供原签名文件；不要把签名私钥提交 Git。自建签名时需在高德控制台配置 `com.qixia.stopwatchnav` 与实际签名 SHA-1，Android Key 在 App 内填写并保存。

## StopWatch 固件

安装 ESP-IDF **5.5.2** 及 ESP32-S3 工具链，在已加载 IDF 环境的终端进入 `stopwatch-nav/firmware/`，首次构建执行：

```powershell
# IDF 的锁文件需要本地组件的绝对路径；只替换该路径，保留依赖版本。
$componentPath = (Resolve-Path './components/78__esp-wifi-connect').Path.Replace('\', '/')
$lock = (Get-Content -Raw './dependencies.lock').Replace('path: components/78__esp-wifi-connect', "path: '$componentPath'")
[IO.File]::WriteAllText((Join-Path $PWD 'dependencies.lock'), $lock, [Text.UTF8Encoding]::new($false))
idf.py -DIDF_TARGET=esp32s3 '-DSDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.defaults.esp32s3;sdkconfig.stopwatch' -DBOARD_NAME=m5stack-stopwatch build
```

`sdkconfig.stopwatch` 固定 StopWatch、16MB 分区及“枫叶精灵”唤醒资源。`dependencies.lock` 保留依赖版本；首次构建需联网下载 `managed_components/` 和模型资源。该目录由依赖管理器生成，不提交 Git。

**必须保留 `components/78__esp-wifi-connect/`**：这是本项目改过的配网组件，不是可随意删除的缓存。`main/idf_component.yml` 通过相对路径引用它，实现手机先配网、再切热点的流程。仓库锁文件将原机器绝对路径规范为相对路径便于交接；首次构建前需执行上面的路径替换。提交时保留规范形式，不提交本机绝对路径。

输出为 `build/xiaozhi.bin`、`build/generated_assets.bin`。构建命令不会烧录。已有绑定的设备使用负责人提供的发布包内 `flash_p8.py`，它先核对分区和活动应用槽，再写程序及资源、回读验证。不要把 IDF 输出中的全片初始化命令当作保留绑定的升级流程。

## 测试与历史工具

本次验收对应：52项 Android JVM 测试、生产 C++ HTTP 协议测试、真实 LVGL 像素测试，以及7项发布保护测试。真机由用户验收，不将桌面测试等同真机结果。

`tools/build.ps1` 和 Python 打包/桌面测试脚本保留原开发机路径，依赖同级 `stopwatch-custom/`、`MotoNav-main/.tools/` 及 MinGW。新电脑优先使用以上原生构建命令；复用脚本需先调整工具路径。C++/LVGL 测试入口是 `tools/test_device_protocol.py`、`tools/test_pages.py`，用 Android 测试生成的帧作为协议样本；先运行 Android 测试，再运行协议测试。LVGL 测试需要固件依赖下载完毕。

`tools/package_p8_progress.py` 是原开发机的发布与回退核对流程，会读取之前的 P6/P7 发布包和构建日志。Git 仓库不包含这些二进制发布历史；首次接手构建并不要求运行这个打包器。需要复用同样的发布/回退流程时，向硬件负责人取得完整 P8-test02 发布目录及所需历史包。
